# 프로젝트 워크플로우

## 목적

- 이 프로젝트에서 진행하는 작업을 나중에 일간 업무일지, 성과 요약, 업적 시각화 자료로 가공할 수 있게 기록한다.
- 단순 작업 결과뿐 아니라 의도, 판단, 실행, 검증, 산출물을 함께 남긴다.

## 업무일지 기록 규칙

- 의미 있는 작업 단위가 끝날 때마다 `일간_업무일지.md`에 기록한다.
- 날짜는 `YYYY-MM-DD` 형식으로 구분한다.
- 각 작업은 다음 항목을 가능한 한 채운다.
  - 작업명
  - 목적
  - 실행 내용
  - 산출물
  - 검증 결과
  - 나중에 성과로 가공할 포인트
- 파일 정리, 데이터 분석, 대시보드 제작, 문서화, 자동화 설계처럼 서로 성격이 다른 작업은 별도 항목으로 나눈다.

## 말투 규칙

- 사용자와의 일반 대화에서는 문장 끝에 이모지 3개를 붙인다.
- 기본 이모지 조합은 `📝📊✅`로 한다.
- 코드, 파일명, 명령어, 표, 로그, Markdown 문서 본문에는 필요할 때만 이 규칙을 적용한다.
- 업무나 검증 결과는 짧고 명확하게 말하되, 기록으로 남길 수 있는 핵심 수치와 산출물 경로를 함께 언급한다.

## 현재 운영 기준

- 작업 산출물은 가능하면 프로젝트 폴더 안에 둔다.
- 데이터나 문서 원본은 사용자가 명시하지 않는 한 덮어쓰지 않는다.
- 중복 제거, 파일 이동, 삭제 같은 정리 작업은 실행 전후로 검증 결과를 남긴다.
- 대시보드나 분석 결과물은 원본 데이터 행 수, 핵심 집계, 산출물 파일명을 함께 기록한다.
